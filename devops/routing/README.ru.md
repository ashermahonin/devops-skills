## Назначение

Маршрутизатор превращает широкий эксплуатационный запрос в безопасный и явный рабочий путь. Он выбирает владельца домена до того, как агент начнёт создавать конфигурации, выполнять команды или менять инфраструктуру.

Машиночитаемый источник истины: [`skills.json`](skills.json). Этот файл объясняет его порядок для человека.

## Порядок работы

1. Классифицируйте запрос через `devops-router`.
2. Определите доменный навык или цепочку навыков.
3. До платформенных команд, конфигурации, ресурсов провайдера, манифестов, конвейеров или средств безопасности запросите актуальную документацию через Context7 MCP.
4. Для production, чувствительных к безопасности или межсистемных работ примените [модель работы уровня principal](principal-operating-model.ru.md): доказательства, след решения, зона воздействия, проверка, откат и передача.
5. Ограничьте изменение минимально полезной областью.
6. Подтвердите результат, зафиксируйте риски и передайте понятный план отката.

## Правила выбора

- Один узкий навык лучше широкой цепочки, если он полностью покрывает задачу.
- Для работ на стыке областей цепочка строится явно, с владельцем каждого этапа и порядком интеграции.
- Состояние окружения доказывают планы, журналы, метрики, трассировки и вывод команд, а не только документация.
- Обращение к Context7 MCP обязательно для актуального синтаксиса и поведения, но не заменяет проверку на целевой среде.
- Инцидент начинается с стабилизации и сбора доказательств; изменения с высоким риском откладываются, пока это не противоречит восстановлению сервиса.

## Частые цепочки

| Тип работы | Цепочка навыков |
| --- | --- |
| Облачная инфраструктура как код | `devops-router` -> `infrastructure-as-code` -> `cloud-operations` -> `security-secrets` |
| Образ приложения и конвейер доставки | `devops-router` -> `container-platforms` -> `cicd-automation` -> `security-secrets` |
| Изменение Kubernetes в production | `devops-router` -> `kubernetes-operations` -> `observability-operations` -> `security-secrets` |
| Инцидент на известной платформе | `devops-router` -> `incident-troubleshooting` -> затронутый доменный навык -> `observability-operations` |
| VPN или частная связность | `devops-router` -> `network-vpn-security` -> `security-secrets` -> `cloud-operations` |

## Что передать в конце

- Понимание задачи и границы изменения.
- Выбранную цепочку навыков и причину выбора.
- Подтверждённую документацию и фактические данные окружения.
- Выполненное изменение или проверяемый план.
- Команды и результаты проверок.
- Риски, допущения, откат и дальнейшие действия.
