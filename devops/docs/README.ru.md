## Назначение

DevOps Skills - это набор рабочих контрактов для агентов, которые работают с инфраструктурой. Он помогает превратить запрос в безопасную последовательность: определить затронутую область, проверить актуальную документацию, установить границы изменения, выполнить или проверить изменение, подтвердить результат и записать всё необходимое для эксплуатации или отката.

Набор работает с Codex, Claude Code и другими агентными средами с поддержкой MCP. Имена навыков остаются на английском, потому что это постоянные идентификаторы. Руководства, схемы и пояснения переведены.

## Устройство набора

| Часть | Где находится | За что отвечает |
| --- | --- | --- |
| Контракт навыка | `devops/skills/<skill>/SKILL.md` | Описывает роль, исходные данные, порядок действий, результат, критерии качества и передачу. |
| Предметная справка | `devops/skills/<skill>/references/` | Содержит повторно используемый рабочий процесс и проверки для конкретной эксплуатационной области. |
| Контракт маршрутизации | `devops/routing/skills.json` | Связывает сигналы запроса с владельцем навыка, правами, сочетаниями, предварительными условиями и обязательными полями передачи. |
| Правила проекта | `devops/templates/` | Даёт краткие локальные правила для совместимых с Codex агентов и Claude Code. |
| Память проекта | `devops/obsidian/project-skeleton/` | Хранит короткие связанные заметки об инвентаре, доступе, выкладках, наблюдаемости и инцидентах. |

`skills.json` - источник истины для автоматического выбора маршрута. [Руководство по маршрутам](../routing/README.ru.md) описывает этот порядок для человека, а [справочник навыков](skills-reference.ru.md) перечисляет все 11 навыков и их справочные файлы.

## Предварительные условия

- Агентная среда с поддержкой MCP, например Codex или Claude Code.
- Context7 MCP, зарегистрированный как `context7` или `mcpcontext7`. Он обязателен перед созданием или проверкой деталей провайдера, платформы, API, CLI, манифеста, конвейера, инфраструктуры как кода, контейнера, сети или средства безопасности.
- Подходящий доступ к целевому проекту и окружению для планов, dry-run, проверок и шагов согласования.

Context7 даёт актуальную документацию, но не доказывает текущее состояние вашей инфраструктуры. Для этого используйте состояние репозитория и провайдера, планы, журналы, метрики, трассировки и вывод команд.

## Установка

Перед изменением каталогов агентов сначала посмотрите план глобальной установки:

```bash
git clone <repo-url>
cd devops-skills
./install.sh --global --target all --dry-run
```

Установите набор для всех поддерживаемых целей:

```bash
./install.sh --global --target all
```

Чтобы подключить его только к одному проекту:

```bash
./install.sh --local /path/to/project --target all
```

| Параметр | Когда использовать |
| --- | --- |
| `--global` | Установить навыки в пользовательские каталоги Codex или Claude Code. |
| `--local PATH` | Подключить локальные навыки и правила, не меняя глобальную конфигурацию. |
| `--target codex`, `claude`, `agents`, `all` | Выбрать агентные среды. По умолчанию используется `all`. |
| `--copy` | Скопировать каталоги для переносимой установки. |
| `--link` | Связать установку с этим репозиторием во время его разработки. |
| `--force` | Заменить установленное содержимое после проверки изменений. |
| `--dry-run` | Показать план действий без записи файлов. |
| `--list` | Вывести список доступных навыков. |

`CODEX_HOME` и `CLAUDE_HOME` могут переопределять стандартные пользовательские каталоги. Установщик не создаёт и не настраивает MCP-серверы.

## Как начать эксплуатационную задачу

Для широкой задачи опишите её обычным языком и дайте `devops-router` выполнить классификацию. До рискованных изменений агент должен явно зафиксировать:

1. Целевое окружение, версию платформы, провайдера, регион и текущее состояние.
2. Выбранный навык или цепочку навыков и причину выбора.
3. Актуальную документацию из Context7 MCP или первоисточника.
4. Зону воздействия: идентичности, данные, сетевые границы, доступность и стоимость.
5. Самый щадящий порядок проверок и быстрый безопасный откат либо локализацию последствий.

Для узкой задачи можно сразу назвать область, например: «проверь этот Terraform plan», «подготовь canary-выкладку Kubernetes» или «диагностируй сбой DNS». Агент всё равно должен применить контракт соответствующего навыка и те же правила безопасности.

## Стандарт безопасности и решений

Перед реализацией, влияющими на production работами, чувствительными к безопасности изменениями и финальной передачей используйте [модель работы уровня principal](../routing/principal-operating-model.ru.md). Она требует:

- отделять наблюдаемые факты от предположений и рекомендаций;
- явно описывать воздействие и обратимость;
- использовать минимальные права для идентичностей, сети и секретов;
- двигаться по лестнице проверок: синтаксис и dry-run, затем план, политики, smoke-тесты и раскатка;
- иметь путь отката или объяснить, почему его нет;
- передавать результат вместе с доказательствами и оставшимся риском.

Перед разрушительными операциями, изменениями production, широким открытием сети, сменой учётных данных, миграциями данных и необратимыми операциями состояния агент должен запросить согласование.

## Память проекта

Устанавливаемый каркас памяти проекта намеренно небольшой. В нём есть индекс и заметки об инвентаре, доступе и секретах, выкладках, наблюдаемости и инцидентах. Держите каждую заметку сфокусированной и связывайте её с индексом. Не записывайте в память действующие секреты, длинные выводы команд или сгенерированные журналы.

Назначение каждого файла описано в [руководстве по памяти проекта](project-memory.ru.md).

## Проверка

```bash
python3 devops/scripts/validate.py
sh -n install.sh
./install.sh --global --target all --dry-run
```

Валидатор проверяет контракты навыков, маршрутизацию, метаданные Context7, локализованную документацию, схемы, ссылки, установщик и случайно попавшие пути конкретного компьютера.
